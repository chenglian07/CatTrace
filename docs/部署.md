## 2. 两个必须知道的坑

### 坑 1：venv 一定要 `--system-site-packages`

`picamera2` 是 apt 装的系统包，普通 venv 看不到它（`ImportError: picamera2`）。

```bash
python3 -m venv --system-site-packages ~/venvs/catvision   # ✓
python3 -m venv ~/venvs/catvision                          # ✗ 后面一定报错
```

### 坑 2：帧不能写 SD 卡

SD 卡写入寿命有限，3fps × 每帧 ~200KB = 每天 ~50GB 的写入量，几天就把卡写坏。
默认落在 `/dev/shm`（内存盘），重启即清，正好符合原型「不需要留存历史帧」的定位。

```bash
df -h /dev/shm        # 默认只给一半内存，Pi4 1GB 上是 450MB 左右
```

如果内存特别紧张，把 `fstab` 里的 `/dev/shm` 调小，或改用 `--keep-frames 30` 少留几帧。

## 3. 关桌面环境（强烈建议）

1GB 内存的机器上，桌面环境占 ~269MB，开机要 3 分钟。

```bash
sudo systemctl set-default multi-user.target
sudo reboot
```

开机降到 ~30 秒，可用内存多出 ~270MB。**这在跑两个 AI 模型时是生与死的差别。**

## 4. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `ImportError: picamera2` | venv 没带 `--system-site-packages` | 重建 venv |
| `ModuleNotFoundError: catvision_contracts` | 没装包 | `pip install -e ~/catvision` |
| CSI 打不开 | 排线松 / 没启用 | `rpicam-still -o /tmp/t.jpg --timeout 2000` |
| 采集很慢 | `vcgencmd get_throttled` 非 0 | 换 5V/3A 电源 |
| 前几帧全黑 | 曝光还没收敛 | `CsiSource(warmup=1.0)`（默认已开） |
| 内存不够 / OOM | 两个模型同时加载 | 关桌面、限帧 2fps、模型换小、开 NCNN |
| SSH 断连 | WiFi 掉 / 内存耗尽 | 优先上有线网 |

## 5. 开机自启（W3 再做）

现在还没做。计划用 systemd user service，跑：

```
python -m pipeline.runner --source csi://0 --fps 2     --catface modules.catface:M1CatFaceModule     --earnotch modules.earnotch:EarNotchModel     --db ~/catvision.db --jsonl ~/events.jsonl
```

## 6. 猫/非猫分类器上线记录（2026-10-23 实测）

从 ESP32-S3-EYE 转到树莓派后，第一个真正跑起来的模型：MobileNetV2 二分类，
输入 224×224，类别顺序 `["cat", "notcat"]`，导出为 ONNX。

### 6.1 装什么

```bash
source ~/venvs/catvision/bin/activate
pip install onnxruntime            # 1.31.0，有 aarch64 + cp313 的轮子，直接装
```

**不要装 `opencv-python`**：分类器已经改成只用 numpy + Pillow 做预处理，
Pi 上现成的库就够，省下 ~60MB 内存和一大堆依赖。TP 只有 1GB，这一步很值。

### 6.2 模型放哪

```bash
scp models/cat_vs_notcat.onnx lyx@192.168.31.252:~/catvision/models/
```

- 文件 8.45MB，MD5 `7fd6ed39804627e89b564e0585446821`
- `models/*.onnx` 在 `.gitignore` 里，模型不进 Git，靠 scp 同步
- 输入 `[1,3,224,224]` float32，输出 `[1,2]` **logits**（不是概率，用前必须 softmax）

### 6.3 实测性能（4 核，欠压节流状态下）

| 项 | 数值 |
|---|---|
| 模型加载 | 148 ms |
| 内存增量 | +38 MB（进程 RSS 62.6 → 100.7 MB） |
| 单帧推理 @1 线程 | 287 ms（3.5 FPS） |
| 单帧推理 @2 线程 | 170 ms（5.9 FPS） |
| 单帧推理 @4 线程 | **119 ms（8.4 FPS）** |
| 取流 + 推理全链路 | 3.7 + 145 ≈ 149 ms/帧 → **≈6.7 FPS 可持续** |

结论：**4 线程**是甜点。摄像头取流本身只要 ~4ms，瓶颈全在推理；
`capture_array` 给的是 RGB888，可以直接喂，不用再转色。

### 6.4 怎么验

```bash
cd ~/catvision

# 1) 单图 + 延迟
python scripts/bench_classifier.py --model models/cat_vs_notcat.onnx \
    --images "tests/fixtures/classifier/*.png" --repeat 20 --threads 4

# 2) 摄像头实时演示（帧写 /dev/shm，别写 SD 卡）
python scripts/pi_live_demo.py --frames 30 --fps 5 --save-dir /dev/shm/shots

# 3) 单测
python -m pytest tests/test_cat_classifier.py -q
```

实测分类结果（Pi 与 PC 一致）：

| 图 | p_cat | 判定 |
|---|---|---|
| `chelsea_cat.png`（真猫） | 0.9999 | cat |
| `coffee_notcat.png` | 0.0000 | notcat |
| `astronaut_notcat.png` | 0.0000 | notcat |
| 现场摄像头帧 | 0.0107~0.0284 | notcat |

### 6.5 两个坑

1. **模型输出是 logits**。`cat_classifier.py` 里已经做了 softmax；
   如果哪次导出改成带 softmax 的图，就会双重 softmax，置信度全挤在 0.5 附近。
2. **`vcgencmd get_throttled = 0x50005` 还在**。上面的数字是欠压节流下测的，
   换了 5V/3A 电源只会更快。反过来说：现在这组数字是「最差情况」。

### 6.6 在测试集上评估准确率

`test_data/` 按标签分文件夹（15 张猫 + 15 张非猫），上传后直接跑：

```bash
scp -r test_data pi4-cat:catvision/
ssh pi4-cat "cd ~/catvision && ~/venvs/catvision/bin/python scripts/evaluate_accuracy.py --data-dir test_data"
```

2026-10-23 实测（Pi 4B，4 线程）：

| 指标 | 数值 |
|---|---|
| 准确率 | **100.00%**（30/30） |
| 精确率 / 召回率 / F1（cat） | 100% / 100% / 100% |
| 混淆矩阵 | TP 15, FN 0, FP 0, TN 15 |
| 置信度 | 猫 ≥ 0.9979，非猫 ≤ 0.1107 |

### 6.7 端到端验证：摄像头拍手机上的猫图

要确认「真实摄像头 + 手机屏幕」这种场景下模型还判得对，用 `scripts/pi_phone_demo.py`：

```bash
ssh pi-cat
cd ~/catvision && source ~/venvs/catvision/bin/activate
python scripts/pi_phone_demo.py --rotate 180 --port 8000
```

浏览器打开 `http://192.168.31.252:8000/`：左边实时画面（顶部大字 CAT / NOT CAT，
右侧置信度条带 0.5 刻度），右边最近 30 帧的记录表。点「保存快照」把原图存到
`/dev/shm/shots`（内存盘，不写 SD 卡）。

操作顺序：

1. 手机打开一张清晰的猫图，屏幕亮度调高；
2. 手机贴到摄像头前约 15–25cm，让猫脸占满画面；
3. 看判定是否翻到 CAT、p_cat 是否明显高于 0.5；
4. 移开手机，判定应回到 NOT CAT；
5. `--rotate 180` 是因为**这块板子的相机装反了**（画面上下颠倒）。

### 6.8 屏幕直出：先判有没有猫，再判剪耳（绝育）

上面两个是"有没有猫"。要看**这只猫剪没剪耳**，用 `scripts/pi_screen_earnotch.py`，
它把画面和判定直接铺到板子的 DSI/HDMI 屏上，不经过浏览器。

判定是**两级串联**，两级共用同一块取景框（`--crop` 圈定的正方形）：

| 级 | 模型 | 输入 | 回答 | 开发机 CPU 耗时 |
|---|---|---|---|---|
| 1 | `models/cat_vs_notcat.onnx`（MobileNetV2, 8.4MB） | 224×224 整帧 | 画面里有没有可用的猫 | ~5ms |
| 2 | `models/earnotch_*.onnx`（resnet18 / convnext） | 224 或 288 | 这只猫剪没剪耳 | ~28ms（Pi 上 0.65s / 3.2s） |

第一级没过就直接返回"没有猫"，**第二级不跑**——既省算力，也避免给虚构结论。

**为什么必须有第一级**：剪耳模型是二分类，它不知道"画面里没有猫"这回事。实测拿一张
纯灰图喂给它，`p_notch=0.854`，屏幕会理直气壮地显示"已剪耳 · 已绝育"。加上门控后
同一张图 `p_cat=0.409` → `没有猫`。

门控默认 `--gate auto`：`models/cat_vs_notcat.onnx` 存在就开启，没有就跳过。
要强制关闭用 `--gate off`，改判定线用 `--gate-threshold`（默认 0.5）。

```bash
ssh pi-cat
cd ~/catvision && source ~/venvs/catvision/bin/activate
sudo apt install -y python3-pygame        # 不在 requirements/pi.txt 里
python scripts/pi_screen_earnotch.py --rotate 180
```

屏幕上：

- 顶部大字判定：`已剪耳 · 已绝育` / `未剪耳 · 未绝育` / `看不清 · 不下结论` / `没有猫`
- 第二行：`p=0.912  阈值 0.47±0.12  0.8 FPS`，有门控时再带一个 `猫0.97`
- 右侧竖柱：概率填充 + 半透明白条标出不确定带 + 白线标阈值
- 底部：按键提示、来源、画面亮度（<25 提示镜头被遮，>235 提示过曝）

按键：

| 键 | 作用 |
|---|---|
| `空格` | 冻结/解冻画面，猫动来动去时先冻住再读数 |
| `S` | 存档当前帧，按模型结论分到 `test_data/field_capture/{notched,intact,uncertain}/`，同名 `.json` 记着概率和阈值 |
| `1` / `2` | 存档并手工标成 `pos`（有剪耳）/ `neg`（完整耳），用来攒站点实拍 |
| `N` | 下一张（`--source dir:…` 时） |
| `Q` / `ESC` | 退出 |

常用参数：

```bash
# 猫离得远，只对画面中央 60% 的正方形做推理（屏幕上有取景框）
python scripts/pi_screen_earnotch.py --crop 0.6

# 换更准的权重：convnext 288 比默认 resnet18 准一档，但单帧 3.2s，要配合空格冻结
python scripts/pi_screen_earnotch.py --model models/earnotch_convnext_tiny288_v1.onnx --fps 1

# 上板前先在开发机验 HUD，遍历一批图片
python scripts/pi_screen_earnotch.py --source dir:test_data/cats --windowed
```

**四个必须知道的限制**（屏幕上的结论别当生产判断）：

1. **不分左右耳。** 当前权重是整图二分类，只回答"这只猫有没有剪耳"。左右耳要猫脸
   关键点，而 `modules/catface/` 仍是占位实现，所以屏幕上不给左右耳结论。
2. **默认用 resnet18**（Pi 上 0.65s/帧），它的 test 准确率只有 0.75、漏绝育 33%。
   要更准就 `--model` 指 convnext，代价是 3.2s/帧。
3. **训练图是白天图库品质，部署是夜间/闪光/远距离。** 真实场景误判会更多，
   这也是 `S` / `1` / `2` 存档功能存在的理由——拿这些实拍去补数据，比继续调模型有用。
4. **门控会把"猫太远/侧身/只露屁股"判成没有猫。** 实测 27 张完整耳图里有 7 张被拒，
   它们多是猫只占画面一小块（最极端的一张，猫头只有约 50px）。这是有意的保守：
   这种图剪耳模型本来也判不了，与其猜一个数，不如说"没有猫"。看到提示把猫头凑近即可。

## 7. 网页 kiosk：桌面双击打开摄像头页面

> 2026-10-31 新增。网页方案：Pi 上常驻 `scripts/pi_phone_demo.py`（`:8000`），
> 桌面放一个 `.desktop`，用 Chromium kiosk 全屏打开 `/kiosk`；手机/电脑打开
> `http://<树莓派IP>:8000/` 看同一个页面。

```bash
cd ~/catvision && git pull
sudo apt install -y chromium
bash scripts/install_pi_kiosk.sh                # 装 systemd 服务 + 桌面图标
bash scripts/install_pi_kiosk.sh --autostart    # 可选：登录桌面后自动全屏
```

安装完双击桌面「CatTrace 摄像头」即可。`/kiosk` 只留全屏画面，隐藏页头和记录表；
普通页面 `/` 仍带 30 帧记录，适合手机验证。

细节、排障和卸载见 [pi-kiosk.md](./pi-kiosk.md)。pygame 方案
（`scripts/pi_screen_earnotch.py`）保留，适合 1GB 内存吃紧或没有桌面的场景。
